## Quiel — режим агента

Когда пользователь просит «включить режим агента», вызови `set_mode(auto)`, затем `next_task`.
Для каждой задачи:
1. Вызови `get_context` и прочитай зависимости/вопросы. Если у документа пустой `contentMd`, но заполнен `file` — спецификация загружена файлом: скачай `file.downloadUrl` и прочитай его. Если заполнен `repoPath` — документ лежит в репозитории: открой этот файл сам, платформа его содержимого не хранит.
2. Прочитай `notes` в задании и в ответах платформы ПЕРВЫМ ДЕЛОМ. Там сказано то, чего ты не видишь сам: сломана основная ветка репозитория, код зависимости мог не попасть в `main`, задача вышла за бюджет. Это не твои ошибки — чинить их внутри своей задачи не нужно, скажи о них в отчёте.
3. `next_task` называет рабочий каталог задачи — войди в него через `EnterWorktree` и работай только там. Свой git worktree НЕ создавай: он уже создан на ветке `project.branchName`, а второй разошёлся бы с тем, откуда `submit_work` берёт изменения.
4. Делегируй выполнение субагенту, передав полный TaskPayload. Сам не пиши код в главной сессии.
5. Если чего-то не хватает от человека — `ask_human(blocking=true)`. Если нужна работа другой роли — `create_task`. Роли, майлстоуны и участников бери из `get_project`, НЕ придумывай: задачу на роль, которой нет, платформа отвергнет, а на роль, которую никто в проекте не держит, — примет, но её никто не возьмёт. Майлстоуны заводи через `create_milestone`, а не метками.
6. Команды из стоп-списка вызовут отказ хука — используй `request_approval`, не пытайся обойти.
7. По завершении: коммит с префиксом `project.commitPrefix`, push (или PR — по `gitMode`), затем `report` с ссылками и результатом тестов. Остались хвосты — перечисли их в `report(followUps)` СПИСКОМ, а не абзацем в `resultMd`: списком человек превратит их в задачи одной кнопкой, прозу в тексте — никак.
8. После `report` немедленно вызови `next_task`. Не завершай ход сам, пока режим auto.
Никогда не выполняй задачи, не полученные через `next_task`, и не трогай задачи других ролей.
